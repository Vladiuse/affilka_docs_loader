Let us imagine a situation where an affiliate wants to send additional parameters to the affiliate program from their tracker (for example, Campaign ID and Source name) and then receive postbacks with these parameters. To add a custom parameter you need to add a key-value pair to the url according to the following syntax: **param_name=${param_name} **where **param_name** is your parameter key and **${param_name}** is its value. Let's consider the above url example and additional custom parameters webID and clickID. The postback URL with such parameters may look as follows:

http://example.com?promo_id=${promo_id}&visit_id=${visit_id}&amount=${amount}¤cy=${currency}&b=${webID}&c=${clickID}

We will store these parameters in our system for the configured postback and will return them to your tracker with a postback once the event is triggered. Of course these parameters have to be familiar to and readable by your tracker.

The tracking link should look like:

**Postback**:

or

or

http://track.me/affiliate?id=**${publisherID} **

in all these examples we store a parameter publisherID. **It does not matter how you name the KEY (b, publisherID, id or whatever), we will only store the value which is indicated in the curly brackets.**

**Tracking link:**

https://casinopartners.com/e4567do?**publisherID**=SOMETHING

or

https://casinopartners.com/e4567do?**publisherID**=[SOMETHING]

or

https://casinopartners.com/e4567do?**publisherID**={SOMETHING}

**Here it matters how the KEY in the tracking link is named. If it does not correspond with the parameter stored in the postback in the curly brackets, we won't have a chance of knowing what parameter this is.**

You can then break down your traffic per different `publisherID`.

We store and send ${publisherID} value**.** So we send the postback http://track.me/affiliate?**btag=${publisherID}** to you. You can not break down your traffic per different `btag` , because we do not store this value and do not send it with postback.

If Cohort report is enabled for your account by the Affiliate program operator, the tab “Cohort Report” will be available within the "Reports" tab.

Cohort Report is a powerful tool that helps you track and evaluate players behavior over time. By grouping players into cohorts based on shared characteristics or actions (e.g., cohort based on registration date, FTD date, deposit date), this report allows you to analyze trends, measure performance, and understand the long-term impact of your strategies.

It can be useful for tracking retention, evaluating campaigns performance, and making data-driven decisions.

**Where to Find It:**

You can find the "Cohort Report" report at the bottom of the "Reports" section or go directly to `/partner/cohort_report`.

The Cohort report is presented in a table format for easy interpretation:

- The first column displays the cohort type (registration date, FTD date, deposit date) along with the cohort period size (e.g., week, month, etc.).

- The second column (Players count) shows the size of each cohort, representing the number of users or entities in that group.

- The remaining columns, combined with the rows, illustrate the behavior or performance of each cohort over time.

By default, the report shows the data for the past 2 months (last month+current month). It represents how players who registered within a span of these 2 months deposit over the set period. The data is grouped by week. It shows cumulative data of all partners and brands. The report is converted into a default report currency set for your user. The exchange rate for the report is set at the current day.

**Cell color distribution.**

The report uses 5 color values as an indication of relative metric values: the darkest color represents the highest metric values, and the lightest color represents the lowest metric values. Each color represents the same relative range of values.

For example, if the highest value in the table is 100, then each color represents a range of 20 (100/5); if the highest value in the table is 50, then each color represents a range of 10 (50/5).


Depending on the settings available to you, you might be able to see the following info in the Cohort report:

- **Cohort type**– indicate the type of action by which the players will be grouped. The available cohort types (actions) are: Player registration date, Player FTD date, Player deposit date.
- **Cohort size**– indicate the period by which the cohort will be grouped. The available options are Day, Week, Month.

In the Filter section you can indicate the action you wish to analyze, set the period for analysis, indicate how player activities should be grouped as well as filter the report by specific Brands, Partners, Campaigns, Countries, etc.

- **Metric**– choose the activities you wish to analyze. For example: Casino bets sum, Deposits sum, Casino NGR. The metrics presented here are the same as in- __Statistics__.
- **Period range**– indicate the period for which the data will be analyzed.
- **Period size**– choose how the data in the report will be grouped period-wise. The available options are Day, Week, Month.
- Use filters such as Partner IDs, Brands, Campaign/Promos IDs, Dynamic tag include/exclude, Traffic sources etc. if you want to limit the scope of the report to specific entities.


Please note that the **Period Range** defines both the cohort selection and the period for analyzing metrics. For example:

If the **Period Range** is set to **01.07.2026 - 31.10.2026**, the cohort type is **Player Registration Date**, the analyzed metric is **Casino NGR**, the cohort and period size is set to **month**:

- The report will include players who registered between **01.01.2024 – 31.03.2024**, grouped by their registration month.

It will display how much **Casino NGR** those players generated during the same period (**01.07.2026 – 31.10.2026**), also grouped by month.
